		-- Numeric
				- PostgreSQL admite varios tipos de tipos de datos numéricos
					- integer or int4 (4-byte integer number).
					- bigint or int8 (8-byte integer number).
					- real (4-byte variable-precision, inexact with 6 decimal digit precision).
					- double precision (8-byte variable precision, inexact with 15 decimal digits precision).
					- numeric (precision, scale), donde la precisión de un numérico es el conteo total de dígitos	
			-- Integer
				- Postges puede convertir un numero con varios decimales y hacer un trunc value de acuerdo al tipo de datos
					+ select 1.123456789::integer as my_field;

				- conversión doble precisión

					+ select 1.123456789::numeric(10,1) as my_field;

	--- hstore
		- primer tipo de datos NoSQL que se implementó en PostgreSQL
		- se utiliza para almacenar pares clave-valor en un solo valor
		- Se debe tene habiliatada la extension hstoe
			+ create extension hstore ;
		- ejemplo: queremos mostrar todas las publicaciones con sus nombres de usuario y con sus categorías:
			+ select p.pk,p.title,u.username,c.title as category from posts p inner join users u on p.author=u.pk left join categories c on p.category=c.pk order by 1;
		- las publicaciones, los usuarios y las categorías de la tabla son tablas enormes
		- almacenar toda la información sobre nombres de usuario y categorías en un solo campo
			+ select p.pk,p.title,hstore(ARRAY['username',u.username,'category',c.title]) as options from post p inner join users u on p.author=u.pk_ left join categories c on p.category=c.pk order by 1;
				- primero coloca en una matriz los valores de los campos de nombre de usuario y categoría
				- luego los transforma en hstore
		- queremos almacenar los datos en una nueva tabla
			+ create table posts_options as select p.pk,p.title,hstore(ARRAY['username',u.username,'category',c.title]) as options from post p inner join users u on p.author=u.pk_ left join categories c on p.category=c.pk order by 1;
		- buscar categoría = 'naranja'. 
			+ select * from posts_options where options->'category' = 'orange';
		- hstore, no es un tipo de datos estructurado, s puede inserte cualquier otro valor clave sin definirlo primero
			+ insert into posts_options (pk,title,options) values (7,'my last post','"enabled"=>"false"') ;
			+ select * from posts_options;

	--- Funciones
		- La estructura de comandos DE UNA FUNCION es la siguiente:
			/- CREATE FUNCTION function_name(p1 type, p2 type,p3 type, ....., pn type)
				RETURNS type AS
				BEGIN
			 -- function logic
				END;
				LANGUAGE language_name
			-/
		- Los siguientes punto aplican para cualquier tipo de función que queramos crear
			- Especifique el nombre de la función después de las palabras clave CREATE FUNCTION
			- Haz una lista de parámetros separados por comas.
			- Especifique el tipo de datos de devolución después de la palabra clave RETURNS
			- Para el lenguaje PL/Pgsql, coloque código entre los bloques BEGIN y END .
			- Para el lenguaje PL/Pgsql, la función debe terminar con la palabra clave END seguida de un punto y coma.
			- Defina el idioma en el que se escribió la función, por ejemplo, sql o plpgsql, plperl, plpython, etc.
			
	--- SQL functions
			- Las funciones SQL son la forma más fácil de escribir funciones en PostgreSQL y podemos usar cualquier comando SQL dentro de ellas.
		-- básicas
			- primeros pasos en el mundo de las funciones SQL
				+ CREATE OR REPLACE FUNCTION my_sum(x integer, y integer) RETURNS
					integer AS $$
					SELECT x + y;
					$ LANGUAGE SQL;
				+ select my_sum(1,2);
			- La función se puede llamar usando la declaración SELECT sin usar ninguna cláusula FROM
				+ CREATE OR REPLACE FUNCTION my_sum(integer, integer) RETURNS 
					integer AS $$
					SELECT $1 + $2;
					$$ LANGUAGE SQL;
			- forma antigua de hacer referencia al parámetro dentro la función.
		-- devuelven un conjunto de elementos
			- cómo crear una función SQL que devuelva un conjunto de resultados de un tipo de datos
			- Crear funcion que tome p_title como parámetro y elimine todos los registros que tengan title=p_title
				- devolver todas las claves de los registros eliminados
					+ CREATE OR REPLACE FUNCTION delete_posts(p_title text) returns setof integer as $$ delete from posts where title=p_title returning pk; $$ LANGUAGE SQL;
			- situación antes de llamar a la función delete_posts :
				+ select pk,title from posts order by pk;
			- situación después de que llamamos a la función delete_posts
				+ select delete_posts('my tomato');
			- tipo de datos setof
				- define un conjunto de resultados de un tipo de datos
				- la función delete_posts definida para devolver un conjunto de enteros por lo que su resultado será un conjunto de datos de enteros
		-- devuelven una tabla
			- es posible que haya casos en los que necesitemos que nuestra función devuelva un conjunto de resultados de varios campos
			- Tomemos el mismo ejrccio nterior de eliminar po titulo
				+ create or replace function delete_posts (p_title text) returns table (ret_key integer,ret_title text) AS $$ delete from posts where title=p_title returning pk,title; $$ language SQL;
			- La única diferencia es que ahora la función devuelve un tipo de tabla
				+ select pk,title from posts order by pk;
				+ select * from delete_posts('my tomato');
			- Las funciones que devuelven una tabla pueden tratarse como tablas reales, en el sentido de que podemos usarlas con las opciones ofin, exist, join , etc.
		-- Polymorphic SQL functions
			- Las funciones polimórficas son útiles para los DBA cuando necesitamos escribir una función que tiene que trabajar con diferentes tipos de datos
			- Ejemplo: 
				- queremos recrear algo que se parezca a la función NVL de Oracle
				- crear una función que acepte dos parámetros y reemplace el primer parámetro con el segundo si el primer parámetro es nulo
					+ create or replace function nvl ( anyelement,anyelement) returns anyelement as $$ select coalesce($1,$2); $$ language SQL;
					- La invocamos o llamamos
						+ select nvl(NULL::int,1);
						+ select nvl(''::text,'n'::text);
						+ select nvl('a'::text,'n'::text);
