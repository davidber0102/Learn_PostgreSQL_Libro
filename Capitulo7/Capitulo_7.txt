		- primer tipo de datos NoSQL que se implementó en PostgreSQL

	--- Funciones
		- La estructura de comandos DE UNA FUNCION es la siguiente:
			/- CREATE FUNCTION function_name(p1 type, p2 type,p3 type, ....., pn type)
				RETURNS type AS
				BEGIN
			 -- function logic
				END;
				LANGUAGE language_name
			-/
		- Los siguientes punto aplican para cualquier tipo de función que queramos crear
			- Especifique el nombre de la función después de las palabras clave CREATE FUNCTION
			- Haz una lista de parámetros separados por comas.
			- Especifique el tipo de datos de devolución después de la palabra clave RETURNS
			- Para el lenguaje PL/Pgsql, coloque código entre los bloques BEGIN y END .
			- Para el lenguaje PL/Pgsql, la función debe terminar con la palabra clave END seguida de un punto y coma.
			- Defina el idioma en el que se escribió la función, por ejemplo, sql o plpgsql, plperl, plpython, etc.
			
	--- SQL functions
			- Las funciones SQL son la forma más fácil de escribir funciones en PostgreSQL y podemos usar cualquier comando SQL dentro de ellas.
		-- básicas
			- primeros pasos en el mundo de las funciones SQL
				+ CREATE OR REPLACE FUNCTION my_sum(x integer, y integer) RETURNS
					integer AS $$
					SELECT x + y;
					$ LANGUAGE SQL;
				+ select my_sum(1,2);
			- La función se puede llamar usando la declaración SELECT sin usar ninguna cláusula FROM
				+ CREATE OR REPLACE FUNCTION my_sum(integer, integer) RETURNS 
					integer AS $$
					SELECT $1 + $2;
					$$ LANGUAGE SQL;
			- forma antigua de hacer referencia al parámetro dentro la función.
		-- devuelven un conjunto de elementos
			- cómo crear una función SQL que devuelva un conjunto de resultados de un tipo de datos
			- Crear funcion que tome p_title como parámetro y elimine todos los registros que tengan title=p_title
				- devolver todas las claves de los registros eliminados
					+ CREATE OR REPLACE FUNCTION delete_posts(p_title text) returns setof integer as $$ delete from posts where title=p_title returning pk; $$ LANGUAGE SQL;
			- situación antes de llamar a la función delete_posts :
				+ select pk,title from posts order by pk;
			- situación después de que llamamos a la función delete_posts
				+ select delete_posts('my tomato');
			- tipo de datos setof
				- define un conjunto de resultados de un tipo de datos
				- la función delete_posts definida para devolver un conjunto de enteros por lo que su resultado será un conjunto de datos de enteros
		-- devuelven una tabla
			- es posible que haya casos en los que necesitemos que nuestra función devuelva un conjunto de resultados de varios campos
			- Tomemos el mismo ejrccio nterior de eliminar po titulo
				+ create or replace function delete_posts (p_title text) returns table (ret_key integer,ret_title text) AS $$ delete from posts where title=p_title returning pk,title; $$ language SQL;
			- La única diferencia es que ahora la función devuelve un tipo de tabla
				+ select pk,title from posts order by pk;
				+ select * from delete_posts('my tomato');
			- Las funciones que devuelven una tabla pueden tratarse como tablas reales, en el sentido de que podemos usarlas con las opciones ofin, exist, join , etc.
		-- Polymorphic SQL functions
			- Las funciones polimórficas son útiles para los DBA cuando necesitamos escribir una función que tiene que trabajar con diferentes tipos de datos
			- Ejemplo: 
				- queremos recrear algo que se parezca a la función NVL de Oracle
				- crear una función que acepte dos parámetros y reemplace el primer parámetro con el segundo si el primer parámetro es nulo

			- queremos recrear la función my_sum usando el lenguaje PL/pgsql:
				+ CREATE OR REPLACE FUNCTION my_sum(x integer, y integer) RETURNS integer AS $BODY$ DECLARE ret integer; BEGIN ret := x + y; return ret; END; $BODY$ language 'plpgsql';

				- 1.encabezado de la función: se define el nombre de la función los parámetros de entrada y el valor de retorno
					+ CREATE OR REPLACE FUNCTION my_sum(x integer, y integer) RETURNS integer AS
				- 2. comienzo del código caracteres $$, este presente al inicio y  final de la función

					+ END;

				- segundo ejemplo
					+ CREATE OR REPLACE FUNCTION my_sum(integer, integer) RETURNS integer AS $BODY$ DECLARE ret integer; BEGIN ret := $1 + $2; return ret; END; $BODY$ language 'plpgsql';

				- En PL/pgSQL, podemos definir todos los parámetros como parámetros de entrada, parámetros de salida o parámetros de entrada/salida.
				- Por ejemplo:
					+ CREATE OR REPLACE FUNCTION my_sum_3_params(IN x integer,IN y integer, OUT zinteger) AS $BODY$ BEGIN z := x+y; END; $BODY$ language 'plpgsql';
						- función my_sum_3_params acepta dos parámetros de entrada (x e y) y tiene una salida del parámetro z.
				- podemos tener funciones que tengan múltiples variables como resultado
				- ejemplo: queremos una función que, dados dos valores enteros, calcule su suma y su producto
					+ CREATE OR REPLACE FUNCTION my_sum_mul(IN x integer,IN y integer,OUT w integer, OUT z integer) AS $BODY$ BEGIN z := x+y; w := x*y; END; $BODY$ language 'plpgsql';
					+ select my_sum_mul(2,3);
						- no es un valor escalar sino un registro, que es un tipo personalizado. Para hacer que la salida se separe en columnas
							+ select * from my_sum_mul(2,3);
				- Podemos definir los parámetros de la siguiente manera:
					- IN: Parámetros de entrada (si se omite, esta es la opción predeterminada)
					- OUT: Parámetros de salida
					- INOUT: Parámetros de entrada/salida
			-- Categorías de volatilidad
				- En PostgreSQL, cada función se puede definir como VOLÁTIL, ESTABLE o INMUTABLE
				- el valor por defecto es VOLÁTIL
					- Una función VOLÁTIL puede hacer cualquier cosa, incluso modificar la base de datos. Puede devolver resultados diferentes en llamadas sucesivas con los mismos argumentos.
					- Una función ESTABLE no puede modificar la base de datos y se garantiza que devolverá los mismos resultados dados los mismos argumentos para todas las filas dentro de una sola declaración.
					- Una función INMUTABLE no puede modificar la base de datos y se garantiza que devolverá los mismos resultados con los mismos argumentos para siempre
				-1. función estable;  la función now() es una función estable.
				-La función now() devuelve la fecha y hora actual que tenemos al inicio de la transacción
					+ begin ;
					+ select now();
					+ select now();
					+ commit;
					+ begin ;
					+ select now();
					+ commit;
				- 2. función inmutable
					+ begin;
					+ select now();
					+ select lower('MICKY MOUSE');
					+ commit ;

		-- Conditional statements
				- lenguaje PL/pgSQL puede manejar sentencias condicionales de tipo IF y sentencias condicionales de tipo CASE.
			-- IF statements
				- la sintaxis de una instrucción IF
					+ IF boolean-expression THEN
						statements
						[ ELSIF boolean-expression THEN
						statements
						[ ELSIF boolean-expression THEN
						statements
						...
						]
						]
						[ ELSE
						statements
				-  escribir una función que, cuando se le den los dos valores entrada x e y, devuelva lo siguiente
					- el primer parámetro es mayor que el segundo parámetro si x > y'
					- 'el segundo parámetro es mayor que el primer parámetro si x < y'
					- los 2 parámetros son iguales si x = y'
						+ CREATE OR REPLACE FUNCTION my_check(x integer default 0, y integer default 0) RETURNS text AS $BODY$ BEGIN IF x > y THEN return 'first parameter is higher than second parameter'; ELSIF x < y THEN return 'second paramater is higher than first parameter'; ELSE return 'the 2 parameters are equals'; END IF; END; $BODY$ language 'plpgsql';
					- existe su forma más corta
						+ IF [...] THEN[...] ELSE[...] ENDIF;
						+ IF [...] THEN[...] ENDIF;
						+ select my_check(1,2);
						+ select my_check(2,1);
						+ select my_check(1,1);
			-- CASE statements
				- instrucción CASE simple
				- sintaxis CASE simple , si tenemos que elegir de una lista de valores
					+ CASE search-expression
						WHEN expression [, expression [ ... ]] THEN
						statements
						[ WHEN expression [, expression [ ... ]] THEN
						statements
						... ]
						[ ELSE
						statements ]
						END CASE;
				- instrucción CASE buscada
				- cuando tengamos que elegir entre un rango de valores
					+ CASE
						WHEN boolean-expression THEN
						statements
						[ WHEN boolean-expression THEN
						statements
						... ]
						[ ELSE
						statements ]
						END CASE;
				- primera sintaxis
					+ CREATE OR REPLACE FUNCTION my_check_value(x integer default 0) RETURNS text AS $BODY$ BEGIN CASE x WHEN 1 THEN return 'value = 1'; WHEN 2 THEN return 'value = 2'; ELSE return 'value >= 3 '; END CASE; END; $BODY$ language 'plpgsql';

					+ create type my_ret_type as ( id integer, title text, record_data hstore );
						- crea un nuevo tipo de datos,
						- Se compone tipo de datos entero + un tipo de datos de texto + un tipo de datos hstore
						- función que devuelva un conjunto de resultados del tipo de datos my_ret_type
							+ CREATE OR REPLACE FUNCTION my_first_fun (p_id integer) returns setof my_ret_type as $$ DECLARE rw post%ROWTYPE; -- declare a rowtype; ret my_ret_type; BEGIN for rw in select * from post where pk=p_id loop ret.id := rw.pk; ret.title := rw.title; ret.record_data := hstore(ARRAY['title',rw.title,'Title and Content',format('%s %s',rw.title,rw.content)]); return next ret; end loop; return; END; $$ language 'plpgsql';
								- muchas cosas se concentran en estas pocas líneas de código PL/pgSQL
									- rw posts%ROWTYPE: la variable rw se define como un contenedor de una sola fila de la tabla
									- for rw in select * from posts where pk=p_id loop: hacemos un ciclo dentro del resultado de la selección, asignando el valor devuelto por el comando select cada vez a la variable rw.
									- return next ret;: devuelve el valor de la variable ret y va al siguiente registro del ciclo for .
									- end loop;: dice a PostgreSQL que el ciclo for termina aquí
									- return;: instrucción de retorno de la función
						- las funciones se ejecutan atómicamente que la función devuelve los resultados no en la ejecución del comando RETURN NEXT sino en la ejecución del comando RETURN colocado al final de la función
