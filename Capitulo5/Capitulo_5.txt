--- Explorando CTE
	-- concepto CTE
		- es un resultado temporal tomado de una instrucción SQL
		- puede contener instrucciones SELECCIONAR, INSERTAR, ACTUALIZAR o ELIMINAR
			+ WITH cte_name (column_list) AS (CTE_query_definition ) statement;
		- quisiéramos crear un conjunto de datos temporal con todas las publicaciones escritas por el autor scotty
			+ with posts_author_1 as(select p.* from posts p inner join users u on p.author=u.pk where username='scotty') select pk,title from posts_author_1;
		- También podríamos escribir lo mismo usando una vista
			+ select pk,title from(select p.* from posts p inner join users u on p.author=u.pk where u.username='scotty') posts_author_1;
		- Ambas consultas dan el mismo resultado, la difeencia radica que el primero utiliza CTE, crea un conjunto de resulados temporales
	-- CTE en PostgreSQL 12
			- A partir de la versión 12 de PostgreSQL, cuenta con dos nuevas opciones dentro de la ejecucion de CTE
				- MATERIALIZED and NOT MATERIALIZED
				- Para materializar el resultado temporal se debe agregar la plaabra materialized
					+ with posts_author_1 as materialized (select p.* from posts p inner join users u on p.author=u.pk where username='scotty') select pk,title from posts_author_1;
				- Para la opcion NOT MATERIALIZED, , no podra verse ninjunto esultado temporal
					+ with posts_author_1 as not materialized (select p.* from post p inner join users u on p.author=u.pk_ where username='scotty') select pk,title from posts_author_1;
			- el valor predeterminado es NO MATERIALIZADO
			- A partir de la versión 12, tenemos que insertar la opción MATERIALIZADA si queremos  que nuestras consultas muestren el mismo comportamiento que teníamos con las versiones anteriores

	-- Consulta recursiva
		- En PostgreSQL, es posible crear consultas recursivas.
		- se utilizan en muchos casos de uso comunes, como consultar tablas que representan menús de sitios web
		- Los CTE recursivos hacen posible tener consultas recursivas en PostgreSQL
		-- CTE recursivos
			- es una construcción especial que permite que una declaración auxiliar se haga referencia a sí misma
			- Es util cuando necesitamos unir a una tabla un número desconocido de veces
			- La solución tradicional implicaría algún tipo de iteración, probablemente por medio de un cursor que itera una tupla a la vez sobre todo el conjunto de resultados
			- se basa en lo siguiente:
				- Una declaración no recursiva, que funciona como una declaración de arranque
					- y se ejecutacuando el término auxiliar se evalúa por primera vez
				- Una declaración recursiva, que puede hacer referencia a la declaración de arranque
			- Estas dos partes se unen mediante un predicado UNION
				+ WITH RECURSIVE tags_tree AS (
					 -- non recursive statment
					SELECT tag, pk, 1 AS level
					FROM tags WHERE parent IS NULL
					UNION
					-- recursive statement
					SELECT tt.tag|| ' -> ' || ct.tag, ct.pk
					, tt.level + 1
					FROM tags ct
					JOIN tags_tree tt ON tt.pk = ct.parent
					)
					SELECT level,tag FROM tags_tree
					order by level;
