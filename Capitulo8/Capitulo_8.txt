---------------------Capítulo 8: Triggers and Rules
		- En PostgreSQL, los eventos posibles vienen dados por las instrucciones SELECT/INSERT/UPDATE y DELETE
		- En PostgreSQL, hay dos formas de manejar eventos:
			- Rules: las reglas suelen ser controladores de eventos simples
			- Triggers: son controladores de eventos más complejos
		- cuándo es más apropiado usar una de ellas en lugar de la otra
		- Los disparadores y las reglas se utilizan a menudo para actualizar acumuladores y para modificar o eliminar registros pertenecen a tablas diferentes de aquella en la que estamos modificando registros
		- herramientas muy potentes permiten realizar operaciones en tablas distintas a aquella en la que estamos modificando los datos
---- Explorando reglas en PostgreSQL
		- las reglas son controladores de eventos simples gestionar todos los eventos que realizan operaciones: INSERT, DELETE UPDATE
		- El concepto fundamental detrás de las reglas es modificar el flujo de un evento
		- Con un evento SE PUEDE REALIZAR con las siguientes condiciones
			- No hacer nada y luego deshacer la acción de ese evento.
			- Activar otro evento en lugar del predeterminado
			- Activa otro evento junto con el predeterminado
		- dada una operación (INSERT) podemos realizar una de estas tres acciones
			- Cancelar la operación
			- Realice otra operación en lugar de INSERTAR.
			- Ejecute INSERT y simultáneamente realice otra operación.

---- Administrar triggers en PostgreSQL
		- definimos las reglas como controladores de eventos simples
		- podemos definir disparadores como controladores de eventos complejos hay registros NUEVOS y ANTIGUOS
		- diferencia entre las reglas y los disparadores es que con los disparadores es posible manejar eventos 
			- INSERTAR, ACTUALIZAR / ELIMINAR / y TRUNCAR
		- antes de que sucedan o después de que sucedan
		- gestionar los siguientes eventos:
			- BEFORE (Antes de ) INSERT/UPDATE/DELETE/TRUNCATE
			- AFTER (Despues de) INSERT/UPDATE/DELETE/TRUNCATE
			- INSTEAD OF (En lugar de) INSERT/UPDATE/DELETE
		- Para las reglas 
			- Para INSERTAR solo hay registro NUEVO 
			- Para INSERCCION el registro NUEVO y ANTIGUO
			- Para ELIMINACIÓN el registro ANTIGUO
		- Si los disparadores y las reglas están presentes simultáneamente en el mismo evento en una tabla,
			- reglas siempre se activan antes que los disparadores
		- Si hay varios activadores en el mismo evento de una tabla
		- primeros pasos para usar disparadores, ejecutan en orden alfabético
	--- Trigger syntax
		+++ CREATE [ CONSTRAINT ] TRIGGER name { BEFORE | AFTER | INSTEAD OF } { event
			[ OR ... ] }
			ON table_name
			[ FROM referenced_table_name ]
			[ NOT DEFERRABLE | [ DEFERRABLE ] [ INITIALLY IMMEDIATE | INITIALLY
			DEFERRED ] ]
			[ REFERENCING { { OLD | NEW } TABLE [ AS ] transition_relation_name } [
			... ] ]
			[ FOR [ EACH ] { ROW | STATEMENT } ]
			[ WHEN ( condition ) ]
			EXECUTE { FUNCTION | PROCEDURE } function_name ( arguments )
			
			where event can be one of:
				INSERT
				UPDATE [ OF column_name [, ... ] ]
				DELETE
				TRUNCATE
		- puntos clave en ejecución de un disparador
			- 1. El evento que queremos manejar, por ejemplo, INSERTAR, ELIMINAR o ACTUALIZAR
			- 2. Cuando queremos que comience la ejecución de TRIGGER (por ejemplo, ANTES DE INSERTAR).
			- 3. El activador llama a una función para realizar alguna acción.
		- La sintaxis de la funcion invocada por el dspaador es la siguiente:
			++ CREATE OR REPLACE FUNCTION function_name RETURNS trigger as
					$$
					DECLARE
					....
					BEGIN
					RETURN
					END;
					$$
					LANGUAGE 'plpgsql';
			- Las funciones a las que llaman los disparadores son funciones que no tienen parámetros de entrada y deben  devolver un tipo TRIGGER
			- toman los parámetros de los registros NUEVOS / ANTIGUOS
			- Ejemplo de la definicion de una posible funcion de TRIGGER en el evento ANTES DE INSERTAR
				+ CREATE TRIGGER trigger_name BEFORE INSERT on table_name FOR EACH ROW
				+ EXECUTE PROCEDURE function_name.
