---------------------Capítulo 8: Triggers and Rules
		- En PostgreSQL, los eventos posibles vienen dados por las instrucciones SELECT/INSERT/UPDATE y DELETE
		- En PostgreSQL, hay dos formas de manejar eventos:
			- Rules: las reglas suelen ser controladores de eventos simples
			- Triggers: son controladores de eventos más complejos
		- cuándo es más apropiado usar una de ellas en lugar de la otra
		- Los disparadores y las reglas se utilizan a menudo para actualizar acumuladores y para modificar o eliminar registros pertenecen a tablas diferentes de aquella en la que estamos modificando registros
		- herramientas muy potentes permiten realizar operaciones en tablas distintas a aquella en la que estamos modificando los datos
---- Explorando reglas en PostgreSQL
		- las reglas son controladores de eventos simples gestionar todos los eventos que realizan operaciones: INSERT, DELETE UPDATE
		- El concepto fundamental detrás de las reglas es modificar el flujo de un evento
		- Con un evento SE PUEDE REALIZAR con las siguientes condiciones
			- No hacer nada y luego deshacer la acción de ese evento.
			- Activar otro evento en lugar del predeterminado
			- Activa otro evento junto con el predeterminado
		- dada una operación (INSERT) podemos realizar una de estas tres acciones
			- Cancelar la operación
			- Realice otra operación en lugar de INSERTAR.
			- Ejecute INSERT y simultáneamente realice otra operación.

---- Administrar triggers en PostgreSQL
		- definimos las reglas como controladores de eventos simples
		- podemos definir disparadores como controladores de eventos complejos hay registros NUEVOS y ANTIGUOS
		- diferencia entre las reglas y los disparadores es que con los disparadores es posible manejar eventos 
			- INSERTAR, ACTUALIZAR / ELIMINAR / y TRUNCAR
		- antes de que sucedan o después de que sucedan
		- gestionar los siguientes eventos:
			- BEFORE (Antes de ) INSERT/UPDATE/DELETE/TRUNCATE
			- AFTER (Despues de) INSERT/UPDATE/DELETE/TRUNCATE
			- INSTEAD OF (En lugar de) INSERT/UPDATE/DELETE
		- Para las reglas 
			- Para INSERTAR solo hay registro NUEVO 
			- Para INSERCCION el registro NUEVO y ANTIGUO
			- Para ELIMINACIÓN el registro ANTIGUO
		- Si los disparadores y las reglas están presentes simultáneamente en el mismo evento en una tabla,
			- reglas siempre se activan antes que los disparadores
		- Si hay varios activadores en el mismo evento de una tabla
		- primeros pasos para usar disparadores, ejecutan en orden alfabético
	--- Trigger syntax
		+++ CREATE [ CONSTRAINT ] TRIGGER name { BEFORE | AFTER | INSTEAD OF } { event
			[ OR ... ] }
			ON table_name
			[ FROM referenced_table_name ]
			[ NOT DEFERRABLE | [ DEFERRABLE ] [ INITIALLY IMMEDIATE | INITIALLY
			DEFERRED ] ]
			[ REFERENCING { { OLD | NEW } TABLE [ AS ] transition_relation_name } [
			... ] ]
			[ FOR [ EACH ] { ROW | STATEMENT } ]
			[ WHEN ( condition ) ]
			EXECUTE { FUNCTION | PROCEDURE } function_name ( arguments )
			
			where event can be one of:
				INSERT
				UPDATE [ OF column_name [, ... ] ]
				DELETE
				TRUNCATE
		- puntos clave en ejecución de un disparador
			- 1. El evento que queremos manejar, por ejemplo, INSERTAR, ELIMINAR o ACTUALIZAR
			- 2. Cuando queremos que comience la ejecución de TRIGGER (por ejemplo, ANTES DE INSERTAR).
			- 3. El activador llama a una función para realizar alguna acción.
		- La sintaxis de la funcion invocada por el dspaador es la siguiente:
			++ CREATE OR REPLACE FUNCTION function_name RETURNS trigger as
					$$
					DECLARE
					....
					BEGIN
					RETURN
					END;
					$$
					LANGUAGE 'plpgsql';
			- Las funciones a las que llaman los disparadores son funciones que no tienen parámetros de entrada y deben  devolver un tipo TRIGGER
			- toman los parámetros de los registros NUEVOS / ANTIGUOS
			- Ejemplo de la definicion de una posible funcion de TRIGGER en el evento ANTES DE INSERTAR
				+ CREATE TRIGGER trigger_name BEFORE INSERT on table_name FOR EACH ROW
				+ EXECUTE PROCEDURE function_name.

				+ insert into new_tags (pk,tag,parent) values (2,'apple',1);
		- función completa con todos los disparadores para INSET, UPDATE, DELETE
			+ CREATE OR REPLACE FUNCTION fcopy_tags() RETURNS trigger as
				$$
				BEGIN
				IF TG_OP = 'INSERT' THEN
				IF lower(substring(NEW.tag from 1 for 1)) = 'a' THEN
				insert into a_tags(pk,tag,parent)values
				(NEW.pk,NEW.tag,NEW.parent);
				ELSIF lower(substring(NEW.tag from 1 for 1)) = 'b' THEN
				insert into b_tags(pk,tag,parent)values
				(NEW.pk,NEW.tag,NEW.parent);
				END IF;
				RETURN NEW;
				END IF;
				IF TG_OP = 'DELETE' THEN
				IF lower(substring(OLD.tag from 1 for 1)) = 'a' THEN
				DELETE FROM a_tags WHERE pk = OLD.pk;
				ELSIF lower(substring(OLD.tag from 1 for 1)) = 'b' THEN
				DELETE FROM b_tags WHERE pk = OLD.pk;
				END IF;
				RETURN OLD;
				END IF;
				IF TG_OP = 'UPDATE' THEN
				IF (lower(substring(OLD.tag from 1 for 1)) in( 'a','b') ) THEN
				DELETE FROM a_tags WHERE pk=OLD.pk;
				DELETE FROM b_tags WHERE pk=OLD.pk;
				DELETE FROM new_tags WHERE pk = OLD.pk;
				INSERT into new_tags(pk,tag,parent) values
				(NEW.pk,NEW.tag,NEW.parent);
				END IF;
				RETURN NEW;
				END IF;
				END;
				$$
				LANGUAGE 'plpgsql';

				CREATE TRIGGER tcopy_tags_ins
				BEFORE INSERT on new_tags FOR EACH ROW EXECUTE PROCEDURE fcopy_tags();
				CREATE TRIGGER tcopy_tags_del
				AFTER DELETE on new_tags FOR EACH ROW EXECUTE PROCEDURE fcopy_tags();
				CREATE TRIGGER tcopy_tags_upd
				AFTER UPDATE on new_tags FOR EACH ROW EXECUTE PROCEDURE fcopy_tags();

			+ select * from new_tags;
			+ select * from a_tags;
			+ select * from b_tags;
			+ update new_tags set tag='apricot' where pk=3;
---- eventos DE triggers
		- Las reglas y los disparadores actúan como declaraciones de nivel de manipulación de datos (DML)
		- cambia los datos, pero no el diseño de los datos ni las propiedades de la tabla
		- disparadores de eventos: se activan en declaraciones DDL (Nivel de definición de datos)
			- el propósito es administrar y reaccionar ante eventos que van a cambiar la estructura de los datos
				- ddl_command_start y ddl_command_end indican respectivamente el comienzo y la finalización del comando DDL
				- sql_drop indica que un comando DROP está a punto de completarse.
				- table_rewrite indica que está a punto de comenzar una reescritura completa de la tabla.
			- existen comandos particulares para crear, eliminar y modificar un disparador
				- CREATE EVENT TRIGGER: agregar un nuevo desencadenante de eventos
				- DROP EVENT TRIGGER: eliminar un disparador existente
				- ALTER EVENT TRIGGER: modificar un activador existente
			- sinopsis para la creación de un nuevo disparador de eventos
				+ CREATE EVENT TRIGGER name
					ON event
					[ WHEN filter_variable IN (filter_value [, ... ]) [ AND ... ] ]
					EXECUTE { FUNCTION | PROCEDURE } function_name()
					- están asociados con un nombre mnemotécnico
					- una función para ejecutar una vez que se disparan
					- los disparadores de eventos no especifican a qué tabla están asociados
					- no están relacionados con ninguna tabla en particular, sino con los comandos DDL
					- deben ser creados por el administrador de la base de datos
			- un par de funciones especiales que pueden ayudar a los desarrolladores
				- pg_event_trigger_commands(): devuelve una tupla por cada comando que se ejecutó durante la instrucción DDL.
				- pg_event_trigger_dropped_objects(): informa una tupla por cada objeto descartado dentro de la misma instrucción DDL
	--- Un ejemplo de un disparador de eventos
			- Ejercicio evita cualquier comando ALTER TABLE en una base de datos.
			- primer paso es definir una función que se ejecutará una vez que se haya disparado el disparador
			- La introspección se realiza mediante la función especial pg_event_trigger_ddl_commands() , que devuelve una tupla por cada instrucción DDL ejecutada
			- La función debe devolver un tipo de disparador, específicamente un tipo de disparador de evento
				+ CREATE OR REPLACE FUNCTION
					f_avoid_alter_table()
					RETURNS EVENT_TRIGGER
					AS
					$code$
					DECLARE
					event_tuple record;
					BEGIN
					FOR event_tuple IN SELECT *
					FROM pg_event_trigger_ddl_commands() LOOP
					IF event_tuple.command_tag = 'ALTER TABLE' AND
					event_tuple.object_type = 'table' THEN
					RAISE EXCEPTION 'Cannot execute an ALTER TABLE!';
					END IF;
					END LOOP;
					END
					$code$
					LANGUAGE plpgsql;
			- si la función descubre que el comando ejecutado tiene una etiqueta 'ALTER TABLE'
			- si la función descubre que el comando ejecutado tiene una etiqueta 'ALTER TABLE' y un tipo de objeto 'table' , genera una excepción que hace que falle toda la instrucción
			- es posible adjuntarla a un desencadenador de eventos:
				+ CREATE EVENT TRIGGER tr_avoid_alter_table ON ddl_command_end EXECUTE FUNCTION f_avoid_alter_table();
					- el activador está activo y la función se activará para cada comando DDL
					- probar el activador y ver si un usuario puede ejecutar ALTER
						+ ALTER TABLE tags ADD COLUMN thumbs_up int DEFAULT 0;
					- lanza una excepción tan pronto como se ejecuta el comando ALTER TABLE
					- para evitar que los usuarios ejecuten comandos particulares,
					- medio de permisos siempre que sea posible
